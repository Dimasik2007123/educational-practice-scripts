# Учебная практика — оформление и сопровождение сделки по продаже недвижимости

Учебный проект по моделированию и автоматизации операций оформления и сопровождения сделки по продаже объекта недвижимости до его передачи покупателю. Репозиторий содержит отчёт, модели предметной области, базу данных PostgreSQL и две консольные реализации: процедурную на Python и объектно-ориентированную на Java.

**Автор:** Зотеев Дмитрий Александрович, группа ИКБО-10-24.

## Цель и содержание работы

Цель практики — разработать модель и программный прототип для автоматизации операций оформления и сопровождения сделки по продаже объекта недвижимости до его передачи покупателю.

Основной процесс рассматривается на уровне одной клиентской заявки. Он начинается с обращения клиента о приобретении недвижимости; входными данными являются сведения о клиенте и его требования к объекту. Основной ответственный — менеджер по продажам; также участвуют клиент, бухгалтер и банк. Этапы процесса: обращение и подбор объекта, бронирование, заключение договора, оплата, передача объекта по акту и выдача ключей, фиксация закрытия сделки. Альтернативный исход — завершение обработки заявки без заключения сделки.

Строительство объекта находится за границами основного процесса. Сведения о строительной готовности используются как данные об объекте. Ведение карточек объектов и общая отчётность по продажам являются поддерживающими функциями системы. Обработка гарантийных претензий выделена в дополнительный модуль, поддерживающий отдельный процесс послепродажного обслуживания и использующий общие сведения о клиентах, объектах и сделках.

В соответствии с отчётом работа включает:

1. Анализ предметной области и выбор средств реализации.
2. Моделирование бизнес-процесса с помощью UML, выделение пользовательских историй и автоматизируемых операций.
3. Проектирование инфологической, логической и физической моделей данных.
4. Разработку десяти алгоритмов и их реализацию на Python и Java.
5. Наполнение базы тестовыми данными и проверку работы программных решений.

## Реализованные операции

Перечень включает операции основного процесса (3–6), поддерживающие функции (1, 2, 7) и функции дополнительного модуля обработки претензий (8–10).

| №   | Операция                        | Модуль Python                | Основной класс Java          |
| --- | ------------------------------- | ---------------------------- | ---------------------------- |
| 1   | Добавление объекта недвижимости | `add_object.py`              | `RealEstateObject`           |
| 2   | Обновление статуса объекта      | `update_object_status.py`    | `RealEstateObject`           |

| 4   | Бронирование объекта            | `book_object.py`             | `Booking`                    |
| 5   | Оформление сделки               | `create_sale.py`             | `Sale`                       |

| 7   | Формирование отчёта по продажам | `generate_sales_report.py`   | `Sale`                       |
| 8   | Добавление претензии            | `add_complaint.py`           | `Complaint`                  |

Python-модули выполняют операции через SQL-запросы с использованием `psycopg2`. Java-реализация представляет сущности предметной области классами и обращается к PostgreSQL через JDBC. Подключение вынесено в `DatabaseService`.

В корне также находятся копии SQL-скриптов; далее используются файлы из `sql/`. Каталоги `out/`, `javapr/out/`, `javapr/target/` и `python/__pycache__/` содержат результаты компиляции и выполнения.

## База данных

В отчёте используется база `company`. Модели данных описывают систему в целом, включая поддерживающие функции и дополнительный модуль обработки претензий. Схема включает 19 таблиц:

- **Справочники:** `contract_type`, `construction_status`, `position`, `keys_type`, `real_estate_type`, `real_estate_status`, `requirement`.
- **Основные сущности:** `employee`, `client`, `real_estate_object`, `account`, `keys`.
- **Бронирования и документы:** `booking`, `sale`, `sale_item`, `complaint`, `complaint_item`, `acceptance_certificate`, `acceptance_certificate_item`.

Для Ф. И. О., паспортных данных и адреса определены составные типы и домены с проверками. Связи и целостность данных задаются первичными и внешними ключами, ограничениями `CHECK`, `UNIQUE` и `NOT NULL`.

## Подготовка и запуск

Понадобятся PostgreSQL с клиентом `psql`, Python 3, JDK и Maven. В `pom.xml` указан целевой уровень Java 8. Команды ниже предназначены для PowerShell и выполняются из корня репозитория, если не указано другое.

### 1. Создание базы данных

Создайте отдельную учебную базу и выполните скрипты в указанном порядке. При необходимости замените пользователя `postgres` своим пользователем PostgreSQL.

```powershell
createdb -U postgres company
psql -U postgres -d company -v ON_ERROR_STOP=1 -f sql/create_tables.SQL
psql -U postgres -d company -v ON_ERROR_STOP=1 -f sql/insert_data.SQL
```

Эти же скрипты можно выполнить через редактор запросов pgAdmin. Они рассчитаны на первоначальное создание и наполнение: повторный запуск может вызвать ошибки существующих типов или уникальных значений.

### 2. Настройка подключения

Создайте файлы `python/.env` и `javapr/.env` с одинаковыми параметрами вашей базы:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=company
DB_USER=postgres
DB_PASSWORD=your_password
```

Замените `your_password` своим паролем. Python использует `python-dotenv`, Java — `java-dotenv`. Размещение `.env` в обеих папках соответствует рабочим каталогам в командах ниже. Файлы с действующими паролями не следует включать в репозиторий.

### 3. Python

Создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install psycopg2-binary python-dotenv
```

Запуск отдельного примера поиска:

```powershell
Set-Location python
..\.venv\Scripts\python.exe search_objects.py
```

Последовательный запуск всех десяти примеров из каталога `python/`:

```powershell
..\.venv\Scripts\python.exe demo.py
```

### 4. Java

Из корня репозитория перейдите в `javapr/`, скомпилируйте исходники и скопируйте зависимости:

```powershell
Set-Location javapr
mvn compile dependency:copy-dependencies
java -cp "target/classes;target/dependency/*" javapr.src.Main
```

`Main.java` демонстрирует десять операций: создаёт объект, меняет его статус, выполняет поиск, оформляет и отменяет бронь перед продажей, создаёт сделку, генерирует код постамата, выводит отчёт и регистрирует претензию с позицией и изменением статуса. Для запуска нужны заполненные справочники, клиент с ID `1` и сотрудник с ID `8`. Сценарий добавляет записи в базу.

## Проверка работы и границы прототипа

Раздел 4.2 отчёта посвящён проверке программного решения; результаты запуска Python и Java представлены в отчёте. Для воспроизведения демонстрации необходимо подготовить базу, настроить подключение и проверить параметры примеров.

Проект является учебным консольным прототипом, демонстрирующим перечисленные десять операций. Создание записи о продаже и установка статуса «продан» отражают оформление продажи, но сами по себе не подтверждают передачу объекта и закрытие сделки. Генерация кода постамата реализована на уровне программы и базы данных; подключение к реальному оборудованию не входит в приведённый сценарий. Подготовка договоров и актов, сверка оплаты, подтверждение фактической передачи объекта и фиксация окончательного закрытия сделки не автоматизированы в этих десяти операциях и остаются действиями участников процесса.

Демонстрационный запуск последовательно вызывает операции основного процесса, поддерживающие функции и дополнительный модуль претензий. Такая последовательность служит проверке функций программы и не означает, что гарантийные претензии являются этапом сделки.
