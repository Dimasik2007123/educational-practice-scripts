# Процедурная реализация

Python 3.13, стандартная библиотека. Данные находятся в data.json.

Из этого каталога:

```powershell
python main.py
```

Из корня проекта:

```powershell
python python/main.py
python python/main.py --date 2026-10-13 --output python/result.json
```

Параметр --data задаёт входной JSON, --date — дату демонстрации, --output — отдельный файл для результата. Исходный JSON не перезаписывается. В демонстрации используются фиксированные идентификаторы объектов, клиентов и сотрудника.

## Функции

| Модуль | Назначение |
|---|---|
| search_objects.py | Подбор карточек по критериям |
| book_object.py | Проверка интервала и бронирование на 14 дней |
| create_sale.py | Проверка комплекта и оформление сделки |
| generate_key_code.py | Поиск свободного кода и регистрация комплекта ключей |
| generate_sales_report.py | Расчёт сумм сделок за период |
| data_utils.py | Поиск записей, проверка данных, чтение и сохранение JSON |

find_free_key_code(occupied_codes) принимает занятые коды и возвращает минимальный свободный код от 100000 до 999999. generate_key_code() проверяет основание выдачи и сохраняет результат в переданном наборе данных.

Пример критериев поиска:

```python
criteria = {"city": "Москва", "min_price": 7000000, "max_price": 8500000}
```

## Ожидаемый вывод

```text
1. Подобрать объекты по требованиям клиента
Найдены объекты: 1, 2, 3, 4
2. Забронировать объект
Бронь 4: объект 1, до 2026-10-27
Повторная бронь отклонена: Объект имеет конфликтующую активную бронь
3. Оформить сделку
Сделка 2: объекты 1 и 3, собственная бронь сохранена как fulfilled
Вход от участников: оплата подтверждена, подписанный акт внесён в тестовые данные
4. Сформировать код для получения ключей
Код: 100001; получение ключей подтверждает участник процесса
5. Сформировать отчёт по продажам
Количество сделок: 2
Сумма сделок: 24000000 руб.
История бронирований: 4 записи; просроченные не удалены
```

Коллекции JSON соответствуют сущностям модели. Бронь действует включительно в дату окончания. Просроченные и отменённые записи сохраняются; после продажи собственная бронь получает fulfilled. При отказе на этапе проверки сделки данные не изменяются.

Подписание документов, подтверждение оплаты и фактическая передача ключей выполняются участниками процесса. Демонстрация использует заранее подтверждённые сведения об оплате и подписанном акте.
