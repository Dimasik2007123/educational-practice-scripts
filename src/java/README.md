# КТ3: пять операций продажи недвижимости

Консольная Java-версия пяти алгоритмов из корневой папки `python/`. Для запуска включена копия данных `python/data.json`; после запуска изменения находятся только в оперативной памяти. Подключение к PostgreSQL не требуется.

Требуется JDK 17 или новее. Проверено на JDK 24. Сторонние библиотеки и Maven не нужны. Команды PowerShell из корня репозитория:

```powershell
New-Item -ItemType Directory -Force -Path build | Out-Null
javac -encoding UTF-8 -d build src/java/*.java
java -cp build Main src/java/data.json 2026-10-13
java -cp build Verification src/java/data.json
```

По умолчанию путь — `src/java/data.json`, дата — `2026-10-13`. Это копия исходного `python/data.json`, включённая для автономного запуска архива. Для прямого сравнения можно передать `python/data.json` первым аргументом. Путь и дата задаются позиционными аргументами. Результат не записывается в исходный JSON. Для проверки используйте файл с теми же коллекциями и полями, что у образца. Деньги — положительные целые рубли в пределах `long`, даты — ISO `YYYY-MM-DD`.

Ожидаемый результат при исходных данных: найдены объекты `1, 2, 3, 4`; бронь 4 заканчивается `2026-10-27`, повторная бронь отклоняется; сделка 2 включает объекты 1 и 3; количество сделок — 2, сумма — 24 000 000 рублей. Код постамата случайный: он должен состоять из шести цифр и не совпадать с занятыми кодами. `Verification` проверяет эти результаты, пограничные случаи и отсутствие изменений при отказе.

Проверка Python для сравнения: `python python/main.py`. Обе программы используют исходную дату и общие тестовые данные. Сообщения об ошибках могут различаться; сравниваются принятые решения и состояние данных.

## Устройство

Для каждой из 15 сущностей из отчёта создан одноимённый предметный класс. `AgencyData` управляет коллекциями: поиск использует метод `matches` каждого `RealEstateObject`, а отчёт — метод `calculateTotal` каждой сделки. `Booking.bookObject` оформляет бронирование, `Sale.createSale` — сделку, а `AcceptanceCertificate.generateKeyCode` формирует ключи на основании конкретного акта. Это методы объектов, а не статические процедуры. `Sale` также хранит свои позиции `SaleItem`. `Person` — общий абстрактный класс для `Client` и `Employee`; они предоставляют разное поведение через интерфейс `Participant`.

Помимо предметных классов существуют вспомогательные классы `Main`, `AgencyData`, `Json`, `Values` и `Verification`: они нужны для работы с наборами данных, запуска, загрузки JSON и проверки программы, но не являются сущностями предметной области. `AgencyData` проверяет идентификаторы, ссылки и ограничения. Сущности хранят внешние ключи как ID, как в JSON; связи по ID разрешаются при работе программы. Акт в демо регистрируется отдельно, так же как в Python его запись добавляется до генерации кода.

На диаграмме данные ФИО, паспорта и адреса представлены полями соответствующих сущностей, поскольку именно так устроены согласованные таблицы и JSON. Дополнительные сущности претензий и аккаунтов отсутствуют в 15 сущностях КТ2 и не участвуют в этих пяти алгоритмах. На основной схеме `models/classes.drawio` показаны поля и предметные методы классов; технические методы доступа и конструкторы для читаемости опущены. Связи по внешним ключам реализованы через идентификаторы, заполненный ромб — состав сделки.
